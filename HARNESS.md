# VibeTags Agent Harness

An agent working in this repository maintains the VibeTags annotation processor: the `@AI*`
annotations, the JSR 269 processor that renders them into per-platform guardrail files, the
merge machinery that keeps multi-module output lossless, and the measurement layers (tests,
corpus, evals, benchmarks) that keep every claim in the docs enforced rather than asserted.
Read [CLAUDE.md](CLAUDE.md) before changing anything: it carries the Tier-1 invariants, each
naming the test that enforces it, and the build order. This file only routes; it repeats no
fact another file owns.

## Where to go

- [CLAUDE.md](CLAUDE.md) - the contract. Invariants, build and test commands, generated
  guardrail regions, and the per-element rule files under `.claude/rules/` that load when a
  matching source file is opened. Note that `CLAUDE.md`, `AGENTS.md`, `GEMINI.md` and
  `llms.txt` at this root are partly generated by VibeTags itself - never hand-edit inside
  `VIBETAGS-START`/`END` markers.
- [docs/](docs/README.md) - the reference documentation router: every document, the question
  it answers, and whether it is maintained reference, unshipped proposal, or frozen archive.
- [vibetags/](vibetags/) - the processor and its whole test suite.
  [docs/TESTS.md](docs/TESTS.md) maps test class to what it covers;
  [docs/LOAD-BEARING.md](docs/LOAD-BEARING.md) states the invariants in full.
- [vibetags-annotations/](vibetags-annotations/) - the `@AI*` annotation definitions
  (`SOURCE` retention, no runtime dependencies). Adding one follows the `add-annotation`
  skill, never improvisation.
- [vibetags-parent/](vibetags-parent/) - the single source of version truth (`<revision>`);
  bump only via `tools/set-version.sh`.
- [vibetags-bom/](vibetags-bom/) - the consumer BOM.
- [vibetags-cli/](vibetags-cli/) - `vibetags init` and `vibetags doctor`, reading platform
  keys and marker strings from the processor at runtime so the CLI cannot drift.
- [examples/](examples/README.md) - consumer fixtures built and verified in CI: Maven and
  Gradle, single- and multi-module, Kotlin, Groovy and Scala.
- [corpus/](corpus/README.md) - third-party repositories built with VibeTags injected, in
  Java and the other JVM languages; the README says what each run asserts and what it has
  found.
- [evals/](evals/README.md) - measured instruction-following: whether the generated rules
  actually bind an agent.
- [load-tests/](load-tests/README.md) - the benchmark harness and recorded release
  baselines.
- [tools/](tools/README.md) - maintenance scripts, each indexed with what it does.
- [action/locked-files/](action/locked-files/README.md) - the CI action that guards
  `@AILocked` ranges against pull-request diffs.
- [oss-fuzz/](oss-fuzz/README.md) - the fuzz harness for the dependency-free JSON reader.
- `analysis/` - dated one-off analyses (surveys, audits, benchmark captures). Point-in-time
  records, not maintained reference.

## Working rules in brief

Verification is the house currency: run the enforcing test named next to a claim rather than
trusting the claim, and treat a skipped gate as not run. The full local gate for a module
change is `mvn clean verify` in that module - lighter invocations stop before the static
analysis the CI steps run. Everything else, including how to add a platform or an annotation,
is routed from [CLAUDE.md](CLAUDE.md) and [docs/](docs/README.md).
