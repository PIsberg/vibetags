ColdAlloc/WarmAlloc/Saved are against a -proc:none baseline, so they carry javac's whole annotation-processing
subsystem as well as VibeTags'. ColdOwn/WarmOwn/SavedOwn are against a no-op processor, which is the only
base a change to this codebase can move (#834). HashOwn is what hashing every source costs over the same no-op
processor, the minimum an exit ahead of the collection walk would spend. Headroom is WarmOwn - HashOwn, an upper bound.

Sources are files on disk, as a build tool hands them to javac, with the fixture's @AIDraft dropped so the
build raises no validation warning (a build that warned is never skipped). i7-1260P, JDK 26, two runs each;
the Own columns agreed to within 1 % between runs. Wall-clock varies far more and is not a result.
